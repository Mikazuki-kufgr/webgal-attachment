# WebGAL Attachment 项目说明

WebGAL Attachment 是给 WebGAL 创作者使用的本地 Live2D 动态附件工具。它把透明 PNG 变成可以跟随人物动作的附件，帮助你给已有立绘添加帽子、兽耳、光环、花朵等效果，不必为每一张附件重新制作一套 Live2D 模型。

首次公测面向经过核验的 Windows x64 / WebGAL MyGO 3.2.0 / Terre 宿主。安装器会核对精确宿主文件；只有版本名称相同，不代表一定符合条件。人物模型、Live2D SDK 和原宿主需自行合法准备。本包不是完整人物素材库，也不是通用 Live2D 模型编辑器。

## 输入与输出

输入是你自己的透明PNG或已有完整附件，以及完整人物模型和可用的锚点配置。制作器用于加载、摆放、检查、保存；高级用户也可以直接修改附件文件。

输出是一份独立附件文件夹，包括图片、配置、人物适配、manifest和使用说明。它能整体备份或分享。添加到游戏后，插件还会生成独立验证剧情，方便在Terre中检查。游戏副本与本地资料库不会自动相互同步。

## 几个概念各自做什么

| 概念 | 实际作用 | 例子 |
|---|---|---|
| 角色 | 把资源按人物分组，方便寻找 | 祥子 |
| 服装/立绘外观 | 选择具体模型入口和依赖 | 冬季校服 |
| 模型文件 | WebGAL实际加载的数据 | 某外观目录里的model.json及其引用资源 |
| Profile/锚点配置 | 描述这个模型的动态跟随点 | 头顶、嘴、画面左耳 |
| 附件本体 | 共享的图片和基础配置 | 一顶草帽 |
| 附件适配 | 某套模型下的锚点和摆放参数 | 草帽在祥子冬季校服上的大小和偏移 |
| 立绘实例ID | 指定当前舞台上具体哪个对象 | 剧情中给某次人物调用设置的ID |

角色分组帮助选择模型，具体模型决定能使用哪个Profile，附件再选择对应适配。系统不会通过人脸照片猜角色。同一角色不同服装通常可以使用相同的语义部位名称，但模型内部点结构不必完全一样，不能随意把某套Profile套给另一套模型。

## 已提供的主要能力

- 前层、后层和前后双层图片，随人物语义锚点运动。
- 拖动与数值调整位置、缩放、旋转及支持的外观效果。
- 同一个附件共享图片，保存多个具体立绘的参数。
- 本地模型导入、依赖检查、已有Profile复用及可见的兼容性复核。
- 附件保存、另存为、完整文件夹导出和添加/更新到游戏。
- Terre卡片与脚本调用，附件显示、隐藏、变换、分离、重新绑定和移除等控制。
- 安装验证、修复和卸载的受管文件保护；用户附件与剧情保持独立。

草帽、兽耳、光环、花朵和玫瑰是普通的可编辑样例，快捷按钮只是方便入口。你可以修改自己的资料库版本；升级不应拿出厂参数覆盖你的调整。默认摆放只是没有匹配适配时的起点，并不意味着所有角色都戴得合适。

## 为什么不能导入任意模型后直接用

图片能跟随，是因为Profile知道模型中的哪些点代表目标部位。缺少摆放参数时可以先用默认值调整；缺少有效锚点时，默认摆放解决不了跟随问题。已有11人97套语义Profile是元数据，不代表附送97套人物模型，也不是全部外观已经逐个完成人工视觉验收。

本次不提供任意模型全自动适配或锚点制作工具。模型结构变化时，系统会区分已知匹配、需要载入检查和真实资源缺失；出现检查提示要看实际跟随效果，不能仅凭成功载入就认定所有锚点适合。

## 拼好模怎样用附件

头、身体、头发等部件仍然是WebGAL中分别调用的立绘实例。一个附件绑定其中一个实例，用户负责选择实际含有所需部位的模型和Profile。例如帽子跟随头部实例；不要因为最终人物叫某个名字，就给不含头部的身体实例套头部锚点。

透明贴图本身不自动表示锚点失效：还要看模型是否保留相应几何和运动数据；若这些数据被删掉，原锚点就可能不可用。不同实例不自动合并成一个锚点网络。跨部件遮挡与同步效果需要自行检查，本次没有对任意拼好模组合做专项视觉保证。
