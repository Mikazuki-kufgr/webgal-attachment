# 一起维护 WebGAL Attachment

欢迎报告问题、改善文档、提交修复和补充测试。原作者不承诺独自持续维护或固定响应时间，希望项目能由使用者共同改进。

## 不会写代码也能参与

在Issues中说明版本、操作步骤、预期与实际结果。文档看不懂、按钮名称令人误解，也是有用的反馈。不要上传完整游戏或未经授权的人物资源。

## 提交代码

1. 较大的功能先开Issue讨论目标、兼容范围和验收方法。
2. 从对应版本源码开始，在自己的分支修改；一次修改围绕一个问题，避免混入无关重构。
3. 提交Pull Request，说明问题、最终行为、验证方法和未验证范围。自动测试与人工视觉结果分别说明。
4. 提交前检查差异，不带入个人路径、密钥、测试游戏、人物模型、SDK二进制或无权再分发的文件。

构建按对应SOURCE包的BUILD.md进行。维护受管文件、保存和升级逻辑时，必须验证失败恢复与用户数据保留；视觉变化需要真实场景检查，不能只凭编译通过。

对MPL-2.0文件的贡献继续遵循MPL-2.0。贡献者须有权提交内容，保留第三方许可和来源；本流程不要求转让著作权。图片等其他内容的授权范围需单独写明。

MPL要求对外分发修改版时提供其覆盖部分的对应源码，但不强制将修改提交回本项目。我们鼓励通过Pull Request回馈；维护权限由项目维护者按实际贡献另行授予，不自动授予。

首次仓库建立后，将整理源码目录与构建入口，再补充精确的仓库内命令。不要用工作目录里的历史构建包代替对应版本源码。
