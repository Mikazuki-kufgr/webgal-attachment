# 同一个附件，怎样适配不同人物

一顶帽子的图片只保存一份；给爱音和祥子戴时，可以分别保存位置、大小和角度。系统根据你载入的具体立绘及其锚点配置选择参数，不是通过图片识别人脸。

## 从角色到具体立绘

- **角色**：资源的分组，例如祥子。导入来源通常是角色根目录，其中可以包含多套服装。
- **服装 / 立绘**：你实际选择的一套外观，例如冬季校服。它对应独立的模型文件和依赖。工作台会显示实际模型路径，普通操作不需要手填路径。
- **锚点配置（Profile）**：告诉附件如何跟随这套模型的头顶、嘴等位置。同一角色的服装可以使用共同的部位名称，但模型内部的点不一定相同。
- **附件适配**：同一个附件在某套立绘的锚点上使用的摆放参数。锚点决定跟随哪里，适配决定图片放多大、偏多少、转多少。

导入时选择包含模型、贴图、动作等依赖的完整目录。角色根下有多套服装时，只会出现本地已导入且有可用配置的外观；锚点元数据不等于已安装模型。导入不会移动或修改原始资源。相同模型的新版语义锚点和旧版专项锚点在普通服装列表中合并展示，详细配置仍可在高级区选择。

## 给同一个附件保存两个人物的参数

1. 在第1步选择**角色**，再选择**服装 / 立绘**，点击**载入所选立绘**。等待人物载入，确认显示的是要使用的外观。
2. 在第2步选择已有附件，点击**载入附件（用于当前立绘）**。也可以从内置样例或自己的PNG开始。
3. 有匹配的适配时，工作台恢复其参数；没有时，使用这个附件的固定默认参数并提示“尚未针对当前立绘调整”。调整跟随部位、位置、大小和角度，再播放人物动作检查效果。
4. 回到第1步，选择另一角色和服装，再点击**载入所选立绘**。当前附件保持不变；已有参数会恢复，没有则从默认参数开始。刚才的调整留在本次草稿里。
5. 为第二套立绘调整参数。切回第一套立绘，应恢复之前的调整。普通切换不需要另点“新增适配”。
6. 在第4步点击**保存附件**，保存在制作器资料库。无需选择游戏，也不要求先把人物复制到游戏。仍保存为**同一个附件**，保留其他适配和一份共享图片。
7. 重新载入已保存附件，分别切换这两套立绘检查参数。需要在游戏中使用时，再在第5步选择游戏，点击**添加 / 更新到这个游戏**。若缺少人物，按提示复制完整模型；每套实际使用的立绘都应有完整依赖。然后在Terre运行结果中给出的独立验证剧情。

切换时尚未保存的适配只保留在当前会话，关闭前请保存。其他立绘有不完整或无效参数时，保存会提醒你切回补齐。重新载入附件、选择其他附件或新建草稿会载入对应内容；不要把重新载入当成同一草稿内的角色切换。

只有需要另一份独立附件时才使用“另存为新附件”。内置样例的快捷按钮优先载入已经保存在制作器资料库中的同一附件；尚未保存过时，载入随包样例或你之前调整的样例来源。修改后点击“保存附件”，再次点击快捷按钮便会打开本地保存版。

## 保存、另存与添加到游戏

- **保存附件**：在制作器资料库中创建或更新当前附件，保存图片、默认参数及全部立绘适配。普通保存保持技术身份；改显示名称不会改变剧情调用ID。
- **另存为新附件**：生成另一套技术身份并保存到资料库，原附件保留。适合制作帽子的另一种独立款式。
- **添加 / 更新到这个游戏**：把当前附件部署到选定游戏，并生成独立验证剧情。不会自动反向更新资料库，也不会修改原剧情；在游戏步骤中改了参数后，仍需点“保存附件”保留到资料库。添加到另一个游戏不需要另存为。
- **导出完整附件文件夹**：位于第4步“更多：复制与分享附件”中，将当前图片和配置写到你选择的目录，保持同一技术身份。适合备份或分享；不会更新资料库或游戏。目标已有同名文件时停止，选择空目录再导出。

资料库位于所安装宿主的 `WebGAL-Attachment-Authoring/workspace/game/attachments-v2/portable/`，每个子目录就是一份完整附件。这里的 `workspace/game` 是制作器自己的工作区布局，不是要求绑定某个目标游戏。保存结果会显示本机完整路径。新窗口可以从“继续编辑已有附件”中的工作区条目载入。

导出的完整子文件夹可以整体复制到另一游戏的 `game/attachments-v2/portable/`。它包含 `attachment.json`、图片、manifest和使用说明，不依赖原图片位置或制作器安装目录；目标游戏仍需要相应人物模型、附件运行支持及正确的模型路径。不同游戏模型路径不同时，需在工作台核对绑定后添加，不能只改角色名字。

首次从游戏载入附件再保存到资料库时，会建立本地版本。若目标已经有同一身份的附件，会先要求确认更新；若检测到文件被手改，会展示差异并要求接受当前内容。资料库与各游戏是独立副本，不能把其中一处保存理解为所有游戏自动同步。

## 改变跟随部位

图片载入后，可以直接在第3步更换“附件跟随位置”。附件会保留图片、大小、角度和相对偏移，以新锚点为参照重新显示，不需要再次导入。若原有偏移较大，换部位后可能仍需调整位置。也允许先选择部位再导入图片。

## 默认参数与缺少适配

默认参数只是稳定的调整起点，不表示新立绘已经校准，也不是上一个人物刚修改的参数。新保存的附件在 `attachment.json` 中保留 `defaultParameters`，人物参数分别放在 `adaptations`。

旧附件没有该字段时，制作器按 Profile ID 排序，取第一套已有适配作为固定起点；保存后写入明确默认值。默认值不会随当前选择变化。内置样例以该样例保存的参数为起点，因此可能需要为其他人物重新调整。

缺少适配可以使用默认摆放参数；缺少可用锚点配置则需要先解决模型适配，不能靠默认参数代替。默认部位在当前模型不存在时，请选择有效的跟随部位后再预览、保存。

## 高级：原样编辑指定适配

普通的“载入附件（用于当前立绘）”优先使用当前模型对应的适配。需要检查指定的旧配置时，展开**高级：原样编辑指定适配**，选中一套并点击**原样编辑所选适配（切换到其立绘）**。这会一起载入该适配的立绘、Profile和参数。只有一套时不会显示多余的适配选择器。

## 剧情调用与拼好模

剧情先调用立绘，再为它添加同一个附件。运行时唯一匹配该模型时使用对应适配；多套候选时需明确Profile。运行时没有已保存适配时，应回制作器校准并保存，工作台的默认参数提示不代表剧情里自动适配成功。

拼好模的头、身体、头发等仍是WebGAL里各自独立的立绘。附件只绑定其中一个立绘ID；请确认所附着部位来自哪套模型，给实际包含该部位的立绘添加附件。例如帽子跟随头部那套模型，不能只看最终合成角色的名字选择身体模型。不同层不会自动合并锚点，跨层遮挡和动作效果需要实际检查。

## 默认样例不必覆盖所有角色

样例展示制作和复用方法，不承诺所有新模型都已有校准参数。用一个附件为两个代表人物各保存一套参数，就能说明这项功能；其他角色由用户按需要逐步增加。

## 在文件中修改某套立绘的参数

打开保存结果给出的完整附件文件夹中的 `attachment.json`。在 `adaptations` 数组中，通过每项 `modelProfile.characterId`、`modelProfile.modelId`、`modelProfile.modelPath` 确认是哪套立绘；其 `preset.modelProfileId` 应与该项 `modelProfile.modelProfileId` 对应。

修改这一项 `preset.placement.offset.x/y`（偏移）、`preset.placement.localScaleX/Y`（横纵缩放）、`preset.placement.rotationOffsetRad`（弧度角度），需要换部位则改 `preset.anchorName` 为该Profile存在的锚点。不要只修改人物名或Profile ID来伪装新增适配。已有分轴缩放时，不要仅改localScale而保留旧X/Y值。只动目标项，其他adaptations和共享asset/images保留。

例如祥子那项的 `placement.offset.x` 改为15，仅改变祥子这一适配。`defaultParameters`是未匹配立绘时的统一起点，不是每个角色的参数，通常无需为单个角色修改它。

文件修改后从“继续编辑已有附件”重新载入；若提示外部修改，检查差异并接受当前内容，制作器会重建校验基线。无需自己改manifest哈希。先保留文件备份，避免稍后把仍在工作台中的旧草稿覆盖回去。

默认样例也允许修改。普通保存会更新资料库中的同一附件，快捷按钮随后使用这个版本；无需再次另存为。旧的样例来源文件保留，安装不会覆盖你此前调好的五套样例。独立的出厂模板与用户活动版本有不同职责：日常编辑的是自己的附件，升级不能用出厂模板覆盖用户改动。

## 通用附件名称与旧剧情

草帽、兽耳、光环、花朵和玫瑰现在使用不带角色名的稳定身份，例如 `v2/straw-hat-both-v1`。人物的 Profile ID 仍保留真实角色来源，这是正常的。旧 `v2/anon-…` 调用由兼容入口继续读取同一附件参数；旧入口不在普通附件列表中重复出现，图片只保存在新附件文件夹中。不要把旧兼容入口当作完整附件导出，分享时使用工作台的导出功能或新文件夹。

升级后首次启动会检查已保存的五套样例；已验证的旧内容迁入中性文件夹并保留迁移备份。检测到用户手改、外来目标或未完成迁移时会保留内容并提示检查；可从继续编辑列表载入、核对并接受改动后再启动。不要手动删除事务记录。自建附件和另存为的身份不因此更改。

## 找到验证剧情与导出位置

添加到游戏会给出 `game/scene/附件测试-草帽-短标识.txt` 一类中文路径。在 Terre 场景列表搜索“附件测试”或附件名称；同一身份重复添加会更新同一脚本，后来只改显示名也不会不断生成新文件。不同附件同名时由短标识区分。旧的英文验证剧情与手改剧情保留，不会为了整理列表被自动删除。

导出成功后，第4步的更多区域会保留“所选目录名称/附件文件夹”的位置，也会显示在成功通知中。浏览器只提供所选目录名称，不提供本机绝对路径；请在文件管理器中回到刚才选择的目录。本地保存与添加到游戏由后台执行，其结果能提供完整绝对路径。

## 完成提示与停止服务

保存先显示正在写入，再显示正在刷新；列表刷新且工作台恢复操作后才显示成功。若文件已写入但刷新失败，会明确区分这两件事，避免误以为必须重复保存。

关闭网页不一定关闭制作器服务。需要验证或安装时运行 `05_停止附件服务.cmd`：服务已经退出时会说明已停止并回收本产品的死亡会话；进程还在但通信失败时会保留错误和PID，不会强杀其他程序。再运行 `03_验证安装.cmd`，占用提示会说明先停止服务或等待维护完成。

旧ID兼容入口会在工作台保存/添加到游戏时同步。直接手改新文件夹时，新ID读取新内容；若旧剧情仍使用旧ID，请在工作台核对后保存/添加一次以同步兼容入口。新剧情使用中性ID。
